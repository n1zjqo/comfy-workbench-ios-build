# Office Strata Bridge

## 0.6.3 手动释放与真实完成状态（需配套部署）

- `release` 保留自动接收聊天，同时持久化 `manually_released`。手动释放后，即使存在先前的 ComfyUI 恢复计划也不会立即重载；新的聊天或成功的手动加载解除待机。`pause` 仍优先并拒绝聊天。
- `GET /workbench/resources` 在 ComfyUI 中只返回协议版本和驻留模型数量，不返回模型名称、文件路径或提示词。状态中的 `comfyResources` 可为空，兼容尚未安装观察接口的旧服务。
- `free_comfy` 要求观察接口可用，在队列为空时提交 `/free`，最多等 30 秒确认模型数归零；期间出现新任务、状态不可读或超时会明确报错。它不释放 Strata，也不会承诺整张 GPU 归零。
- 完成的控制响应在维护锁清除后再读取状态，避免成功后仍显示“切换模型”。
- 部署需同时更新控制桥和身份组件，先备份文件及状态文件，等两端任务自然结束后重启。回滚旧桥前要恢复旧状态文件，避免遗留新版待机偏好。

## 0.6.2 自动协调（需部署后生效）

新增 `gpu_coordinator.py` 与 `comfy_workbench_identity/gpu_gate.py`。示例默认关闭自动协调；必须同时安装 ComfyUI 队列组件并通过确认，才设置 `comfy_priority_enabled: true`。

- ComfyUI 的单个队列工作线程在取出任务前向本机控制桥请求显存。当前 Strata 回复自然结束后，控制桥确认请求归零、模型卸载，再许可取出 ComfyUI 任务。等待时任务仍在原队列，可以取消；请求失败时继续等待，不冒险加载两边模型。
- 所有客户端通过同一个 ComfyUI 队列，因此手机切后台、电脑网页提交、多任务排队均受同一规则管理。所有 Strata 推理客户端仍须经过控制桥。
- 队列工作线程报告空闲，且运行/等待队列持续清空 10 秒后，释放 ComfyUI 驻留模型与缓存，检查剩余显存，再恢复 Strata。新任务到达会重新让出显存；已发放的取任务许可不会仅凭计时失效。
- 手动暂停优先，队列结束后仍保持暂停。文件任务在 ComfyUI 生产期间显示等待，不消耗步骤；恢复后继续，取消和写入审批保持原规则。
- 新增本机认证接口 `/workbench/comfy/acquire`、`/workbench/comfy/idle`，只接受回环连接及既有 Bearer 密钥。外网地址、密钥、模型配置均不写入源码。
- ComfyUI 自定义组件设置 `WORKBENCH_GPU_COORDINATION=1`、`WORKBENCH_STRATA_BRIDGE_URL=http://127.0.0.1:8086`、`WORKBENCH_STRATA_KEY_FILE=/path/to/existing-key`。密钥通过文件读取，不放在环境变量值或日志中。`GET /workbench/gpu-gate` 只返回组件是否安装及是否等待。
- 此版本根据已核对的 ComfyUI `PromptQueue.get` / `not_empty` 结构实现。更新 ComfyUI 后应再次确认队列结构；组件不可用时不会自动加载 Strata。部署和回滚时须先让两个服务的当前任务自然完成；关闭自动协调应先暂停、卸载 Strata，再移除队列入口。

测试：分别运行 `python -B test_bridge.py -v` 和 `python -B test_gpu_coordinator.py -v`，不创建网络监听、不调用真实 GPU。不要递归导入自定义节点包；该入口只在真实 ComfyUI 中注册路由。

提供模型控制、聊天转发和受限文件任务。仅 Python 3.10+ 标准库，不依赖额外 Python 包。示例地址和路径必须经实际服务器核对后填写。

## 两种关闭方式

- `release`：仅在网关和上游都空闲时卸载；后续请求可以自动唤醒。
- 卸载后最多等待 15 秒让显存回收及采样数据刷新，避免紧接着的自动唤醒被旧读数误拦截。等待期间保持维护状态，后续加载仍必须通过真实队列和显存检查。
- `pause`：先持久化关闭请求入口，再等待正在生成的请求结束后卸载。状态文件损坏时保持暂停；卸载失败也不重新开放入口。`resume` 手动恢复并加载。
- `reload`：空闲时卸载并重新加载。检查 ComfyUI 运行/等待队列和空闲显存。
- `free_comfy`：单独确认后，仅在 ComfyUI 两个队列均为空时请求释放驻留模型。Strata 暂停期间也可执行，保持暂停且不会加载 Strata 模型，避免显存不足时无法恢复。不同软件同时操作 GPU 的竞态仍需实际资源管理，不能保证独占显卡。
- ComfyUI 的 `/free` 可以用 HTTP 200/204 空响应确认收到请求；仅此已知操作允许空正文，完成与否另由驻留模型观察接口核对。

## 部署约束（必须在执行前取得批准）

1. 只读确认现有 Strata 配置、端口、systemd 单元及 API；备份配置后，将原推理服务从网络监听改为 `127.0.0.1:18086`。具体启动参数需依据现场版本，不能猜测。
2. 将本桥作为原 8086 端口的唯一网络入口。所有 App、Hermes 和其他客户端必须经过本桥。不能同时保留可绕过网关的旧网络端口。
3. 使用现有 Strata 密钥，不把密钥放在公开源码、命令行或日志中。配置和状态目录仅服务账户可读。`server_id` 创建一次后保持不变，手机用于校验内外网目标。
4. 控制桥需要独立常驻服务；示例配置默认只监听本机。改为局域网监听、启停既有服务、修改 DDNSTO 转发都需批准。
5. DDNSTO 为此入口添加独立 HTTPS 映射。现有 ComfyUI 映射继续使用原端口。手机填写桥的内网/公网地址，首次验证后保存设备 ID，密钥存 iOS Keychain。
6. 回滚：先停止桥，再恢复已备份的原监听配置和服务。保留暂停状态文件和原始模型文件。部署期间应确保两边队列空闲。

设备标识、网页静态资源和原健康检查不要求密钥，其余接口要求 Bearer 密钥。禁止重定向和环境代理；只可转发给配置中的本机上游。兼容 Chat Completions、Responses、Completions、Messages 的推理入口和 load/unload。保留原网页聊天所需的首页、字体、静态文件、健康检查、读取设置及共享默认设置接口；运行配置变更、MCP 配置、会话槽写入和图像生成等额外接口不开放，需在本机管理。网页聊天仍需用部署后的实际版本验收。App 对话支持文字和缩小后的 JPEG；不读取浏览器 Cookie。

## 任务执行范围

在办公室专用目录内列出文件、读取 UTF-8 文件、生成新文件；写入需手机显示完整文件名和内容并确认。不能覆盖既有文件、访问目录外路径或执行任意命令。一次运行一个任务，最多 12 步；取消后不再执行后续工具，当前模型生成自然结束。审批单次有效并绑定服务器保存的参数。重启后内存任务不自动恢复或重放，手机保留已取得记录并提示任务不存在。

后续如需运行项目检查或系统命令，应单独增加明确的命令白名单、工作目录和执行权限；不把任意 shell 暴露给模型。

## 验证

`python -B test_bridge.py -v` 使用虚构上游、临时任务目录，不监听端口，不调用模型或读取剪贴板。2026-10-29 修订通过 31 项检查，覆盖空响应、卸载后显存采样延迟、暂停及审批保护。本次修订只涉及服务器，协议兼容已编译的 iOS 0.6.0，不需要重编 IPA。实际服务器的验收记录与源码测试分开保存；长时间使用、手机真机、图片输入与断线恢复仍需分别验证。

## ComfyUI 双地址身份节点

配套 comfy_workbench_identity 目录是可选 ComfyUI 自定义节点，只注册 /workbench/identity，不增加画布节点、不修改工作流。部署前需单独批准复制至 ComfyUI 的 custom_nodes、设置固定 WORKBENCH_SERVER_ID UUID 并在队列空闲时重启 ComfyUI。此接口不返回密钥或机器信息；它用于避免意外连接另一台机器，不替代 TLS，局域网仍须可信。未部署时 App 仍可使用原单地址连接。
